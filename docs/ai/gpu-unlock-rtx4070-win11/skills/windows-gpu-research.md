# Процедура для этой платы

1. Сверить PCI device/subsystem/revision и архитектуру через NVAPI; имя модели недостаточно.
2. Проверить pinned source, build manifest, no-write контракт и host tests.
3. Сохранять экспериментальные устройства вне default/all и вне resume.
4. До любого boot-test получить доступ к штатному восстановлению и согласовать
   офлайн-этап у машины. Не менять EFI, BCD, Secure Boot или драйвер из build-скрипта.
5. Сырые ROM/UEFI captures держать локально. Публиковать код, лицензии и агрегированный статус.
6. После успешного аппаратного запуска проверять конечный Windows-драйвер,
   численную корректность и cold stock/experiment/stock. Не выдавать getter за ускорение.

Это проектная процедура, не квалифицированный универсальный skill установки unlock.
Пределы текущей реализации перечислены в CHECKS.md и PROJECT_CONTEXT.md.
